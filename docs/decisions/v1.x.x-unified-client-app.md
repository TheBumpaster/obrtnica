# Decision: Unified Client App (Web + Electron)

**Date:** 2025-12-18  
**Decision:** Merge `apps/web` and `apps/desktop` into a single `apps/client` app (Next.js as source of truth) with Electron builds produced via electron-builder wrapping the Next.js standalone output.

## Context
- Maintaining separate web and desktop codepaths increased drift and duplicated UI setup.
- Next.js already supports standalone output suitable for bundling with Electron.
- Desktop experience will be produced from the same codebase to guarantee parity by construction.

## Chosen Approach
- Rename `apps/web` → `apps/client`; remove `apps/desktop`.
- Keep Next.js as the single UI source; add Electron main/preload under `apps/client/electron`.
- Build flow:
  - `pnpm client:build` → Next.js standalone output.
  - `pnpm client:build:electron` → compile Electron main/preload (tsconfig.electron.json) + electron-builder to package the standalone output.
- Dev flow:
  - `pnpm client:dev` for web.
  - `pnpm client:dev:electron` to launch Electron against the dev server.

## Rules Adjustments
- Remove cross-platform parity rule (parity guaranteed by single codebase).
- Update UI rules to scope to `apps/client` and keep shadcn MCP-first enforcement.
- Update architecture/file-structure/commands rules to reference `apps/client` paths and scripts.

## Impacted Docs & Tooling
- CI workflow builds client web artifact and client Electron artifact.
- Release docs updated to new artifact names and paths.
- Runbook updated with new commands and dev flow.
- Root `components.json` now points to `apps/client`.

## Notes
- Web code remains the source of truth; no desktop-specific code migration retained.
- Electron bundles include `.next/standalone`, `.next/static`, and `public` via electron-builder extra resources.
