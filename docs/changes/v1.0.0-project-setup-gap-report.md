# v1.0.0 Project Setup – Compliance Gap Report

## 1. Duplicate Drizzle Schemas
- **Rule:** `.cursor/rules/drizzle-schema-organization` – all schemas must live in `packages/db`.
- **Finding:** `apps/api/src/db/schema.ts` and `apps/worker/src/db/schema.ts` each defined their own tables, risking drift.
- **Fix:** Added `packages/db` with canonical tables and re-exported schema to API/worker (see `docs/changes/v1.0.0-db-shared-schema.md`).

## 2. GDPR Domain Logic Outside `packages/core`
- **Rule:** `.cursor/rules/architecture-boundaries` – business logic belongs in `packages/core`.
- **Finding:** GDPR export/erasure workflows were implemented directly in worker consumers.
- **Fix:** Implemented `createGdprService` + repository interfaces in `packages/core`; worker now injects a Drizzle-backed repository (apps/worker/src/services/gdpr-repository.ts) and keeps orchestration-only consumers.

## 3. API Validation Bypassing `packages/validations`
- **Rule:** `.cursor/rules/api-mvp-patterns` – every tRPC procedure must validate input via shared schemas.
- **Finding:** `sampleRouter.create` defined ad-hoc Zod schemas inline.
- **Fix:** Added `packages/validations/src/sample.ts` and updated router to consume the shared schemas.
