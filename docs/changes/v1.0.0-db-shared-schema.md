# v1.0.0 – Shared Drizzle Schema Package

## Summary
- Added `packages/db` to host the canonical Drizzle schema and exports.
- Updated `apps/api` and `apps/worker` to consume the shared schema instead of defining their own copies.

## Why
- `.cursor/rules/drizzle-schema-organization` requires a single schema source under `packages/db`.
- Keeps API/worker thin and prevents schema drift between services.

## Impact
- `drizzle.config.ts` in `apps/api` now re-exports the shared schema (CLI compatibility preserved).
- Domain services (including GDPR + audit flows) continue to operate via the shared schema.
- Tests and migrations run against the unified definitions.
